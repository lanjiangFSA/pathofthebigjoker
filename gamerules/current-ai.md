# 当前 AI 打牌逻辑（Web 实现版）

本文描述 **本仓库当前已实现** 的机器人策略，代码主要在 `logic.js`：`candidates` → `pickLead` / `pickBeat` → `botMove`。配合理念见 `howtocollabrate.md`；目标是 **红蓝队得分最大化**（抓住对手名次），不是个人最快出完。

## 1. 总流程

```
轮到 bot
  → candidates(手牌, 将牌, 桌面牌型) 生成合法着法
  → 无桌面：pickLead 选领出
  → 有桌面：pickBeat 选压制或 null（不要）
  → play / pass
```

服务端约 1.8–2.5 秒调度一次 `botMove`；人类超时走 `autoAct`（跟牌一律不要，领出打最小单张），与 bot 策略无关。

## 2. 角色：主攻 / 辅助

发牌后 `assignRoles`：每队三人按 `handStrength` 排序——最强为 **main（主攻）**，其余为 **support（辅助）**。

`handStrength` 大致加权：

- 大小怪、将牌、A/K、同点多张；
- 额外加分：手中已能组成的五路（同花顺 / 炸弹类 / 葫芦等更整齐者更高）。

角色影响领出谨慎度、喂牌与是否保留炸弹。

## 3. 候选着法 `candidates`

- 枚举单张、对子、三张（含用怪补全）、纯怪对/三；
- 领出或跟五张时再枚举五路；
- 过滤非法 / 压不住桌面者；
- 排序优先：**怪花费低** → 牌型 kind 小 → rank 小（偏「便宜」的自然牌）。

## 4. 珍惜大小怪 `wildSpendCost`

对每条候选估计「浪费怪」代价（越高越差）：

| 情况 | 代价倾向 |
|------|----------|
| 不用怪 / 纯怪出手 | 0（单出大怪、对怪等正常） |
| 怪垫 **J 以下** 对子/三张（如 5+大王＝对5） | **很高** |
| 怪垫 J/Q/K | 中等 |
| 怪垫 A/2 或强五路（四带一及以上） | 较低 |

`pickFrom` 在阈值内选代价最低着法；超阈值且不允许强行时返回 `null`（跟牌则不要）。

## 5. 领出 `pickLead`（优先级概要）

1. **压制短敌**（敌方最短手 ≤5）  
   - 1 张：优先五路或对子等「对不上」的长度；  
   - 2–3 张：三张 / 中等五路 / 小单等；  
   - 残局允许提高怪花费上限。

2. **喂队友**（辅助，且队友较短）  
   - 目标优先「最短队友」，否则主攻；  
   - 按剩余张数选路（放牌表）：

   | 队友张数 | 优先路子 |
   |----------|----------|
   | 10 / 5 | 5 路 |
   | 9 / 7 / 4 / 2 | 2 路 |
   | 8 | 3 路 |
   | 6 / 3 / 1 | 1 路 |
   | 11–12（软喂） | 小单或中等对 |

3. **开局试探**（手牌 ≥18）  
   - 主攻且有强回手时才可探中等五路；  
   - 否则中等对 / 小单；**辅助不强开弱五路**。

4. **主攻残局**（己方 ≤10）  
   - 按自身张数走与上表类似的成型路子。

5. **默认**  
   - 避免炸弹与弱五路；在怪花费阈值内取较便宜着法。

## 6. 跟牌 `pickBeat`

### 桌面是队友

- 队友只剩 ≤3 张：一般 **不压**。  
- **默认不要**（含对子尽量不过）。  
- 例外：  
  - **接牌喂主攻**：辅助 + 短队友 ≤8 + 桌面为 **小单** 且不大 → 可用非怪/低花费着法接手；  
  - **阻敌残局**：敌方很短且出牌者极短 → 可压。  
- 从队友手里接牌时 **几乎不花大小怪**。

### 桌面是敌方

- 敌方或出牌者很短（≤3）：可压，**允许花怪**。  
- 中盘：主攻尽量 **留炸**（非必要时不用四带一及以上）；  
- 普通压制：怪花费超阈值则 **宁可不要**，避免 5+大王 这类亏本顶牌。

## 7. 明确未做（后续可增强）

- 完整记牌（已出多少大怪/关键点）；  
- 搜索 / 神经网络等重型模型；  
- 精细信号（先大后小等）与完整守门推演。

当前是 **启发式团队策略 + 怪花费约束**，用 `test-collab.js` 覆盖角色、放牌表、不压队友对子、不垫低对、慎开五路等回归。
